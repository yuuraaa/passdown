# バックアップからの復元手順書

## バックアップ

Passdown は SQLite のデータベースを自動でバックアップするように実装されています。

バックアップ先は `PASSDOWN_BACKUP_DIR` で指定でき、既定値は `/data/backups` です。

バックアップには次の2種類があります。

- 日次バックアップ
- マイグレーション適用前のバックアップ

### 日次バックアップ

アプリケーションのプロセス内で、リクエスト時に前回の日次バックアップから24時間以上経過しているかを判定し、経過している場合にバックアップを作成します。判定は既定で1時間に1回です。

バックアップのために Hono とは別の定期実行プロセスや Worker は起動しません。固定時刻に実行する方式ではないため、プロセスの停止中やリクエストがない間は作成されず、その後のリクエストで条件を満たしたときに実行されます。

作成されるバックアップのファイル名は次の形式になります。

```text
passdown-<日時>.sqlite3
```

日次バックアップは既定で14世代を保持し、上限を超えた場合は古いものから削除します。

### マイグレーション適用前のバックアップ

起動時に未適用のマイグレーションがあり、かつ既存の DB にテーブルがある場合、マイグレーション適用前にバックアップを作成します。バックアップ完了後にマイグレーションを適用します。

作成されるバックアップのファイル名は次の形式になります。

```text
before-migration-<日時>.sqlite3
```

マイグレーション適用前のバックアップは既定で5世代を保持し、上限を超えた場合は古いものから削除します。

初回起動時の空の DB では、戻す対象がないためマイグレーション前バックアップは作成しません。

### 設定

| 環境変数 | 既定値 | 内容 |
| --- | --- | --- |
| `PASSDOWN_BACKUP_KEEP_DAILY` | `14` | 保持する日次バックアップの世代数 |
| `PASSDOWN_BACKUP_KEEP_MIGRATION` | `5` | 保持するマイグレーション前バックアップの世代数 |
| `PASSDOWN_BACKUP_DIR` | `/data/backups` | バックアップの保存先 |
| `PASSDOWN_BACKUP_INTERVAL_MS` | `86400000` | 前回の日次バックアップから次の作成までの経過時間（ミリ秒） |
| `PASSDOWN_CHECK_INTERVAL_MS` | `3600000` | リクエスト時に作成要否を確認する最短間隔（ミリ秒） |

バックアップは DB と同じストレージ上に保存します。別のマシンへの転送や暗号化は Passdown では行いません。ボリュームや PVC 自体の保全は別途行う必要があります。

バックアップの実行は Activity には記録されません。

## バックアップの確認

保存されているバックアップは次のコマンドで確認できます。

```sh
passdown backup list
```

出力には、復元時に指定できる日時とバックアップ種別が表示されます。

例:

```text
20260923-114512.123  before-migration
20260923-101530  daily
20260922-094812  daily
```

## 復元

復元にはサーバープロセスがDBを開いていない状態にする必要があります。

起動時に `PASSDOWN_START_MODE=restore_wait` が指定されていると、プロセスは起動したまま DB 接続、マイグレーション、HTTP/MCP サーバー、自動バックアップを開始せず、CLI の操作を待つ待機モードで起動します。復元は自動では実行されません。既定の `server` では通常どおり起動します。これ以外の値は起動エラーになります。

1. サーバーを完全に停止します。
2. 起動モードを `restore_wait` に切り替え、アプリケーションを起動します。
3. 待機モードで `passdown backup list` を実行し、復元する日時 ID を確認します。
4. 待機モードで `passdown backup restore <日時ID>` を一度だけ実行し、成功を確認します。
5. 待機モードで起動されたサーバーを完全に停止してから、起動モードを `server` に戻し、サーバーを起動します。
6. 起動ログと復元後のデータを確認します。

### 復元対象の選択

復元対象はバックアップファイルのフルパスではなく、日時で指定します。

```sh
passdown backup restore <YYYYMMDD[-HHmmss[.SSS]]>
```

日付だけで候補が1件に絞れる場合は、日付だけで指定できます。

```sh
passdown backup restore 20260923
```

同じ日に複数のバックアップがある場合、復元は実行されず、候補が表示されます。その場合は時刻まで含めて指定します。
マイグレーション前バックアップはミリ秒まで表示され、同じ秒に複数あっても一覧の日時で指定できます。

```sh
passdown backup restore 20260923-114512.123
```

例:

```text
$ passdown backup restore 20260923
複数のバックアップが該当します: 20260923
20260923-152044.000  before-migration
20260923-114512.123  before-migration
20260923-101530  daily
日時を詳しく指定してください。
```

### `backup restore` が行う処理

`passdown backup restore` は、`PASSDOWN_DB_PATH` と `PASSDOWN_BACKUP_DIR` を使って復元を行います。
`backup list` と `backup restore` は復元先の DB への接続を開かず、`PASSDOWN_MCP_ALLOWED_HOSTS` の設定も不要です。`backup restore` は検査のため、一時ファイルにコピーしたバックアップを読み取り専用で開きます。

復元時には次の処理を順に行います。

1. 指定された日時に一致するバックアップを検索する
2. 復元対象が1件に確定していることを確認する
3. バックアップファイルを復元先と同じディレクトリの一時ファイルにコピーする
4. 一時ファイルを SQLite で開き、`quick_check` で整合性を検査する
5. 現在の DB ファイルと、存在する場合は `-wal`・`-shm` ファイルを日時付きの名前で退避する
6. 検査済みの一時ファイルを `PASSDOWN_DB_PATH` に配置する
7. 復元結果を表示して終了する

`quick_check` は、バックアップのコピーに破損がないかを、現在の DB を退避する前に確認するために実行します。結果が `ok` でない場合や一時ファイルを SQLite で開けない場合は、復元を中止します。ただし、`quick_check` は UNIQUE 制約、インデックスの内容とテーブルの内容の一致、外部キー違反までは検査しません。

現在の DB と WAL / SHM は削除せず、復元前の状態として退避します。
検査や配置が失敗した場合は、退避済みのファイルを元の場所に戻します。

概念的には次のようなファイルが残ります。

```text
/data/passdown.sqlite3.before-restore-<日時>
/data/passdown.sqlite3-wal.before-restore-<日時>
/data/passdown.sqlite3-shm.before-restore-<日時>
```

実際に存在するファイルだけが退避対象になります。

バックアップ元のファイルは移動せず、一時ファイルへのコピーから復元します。そのため、復元後も元のバックアップは `/data/backups` に残ります。

### 復元後の起動

復元が成功したら待機モードを終了し、`PASSDOWN_START_MODE=server`（または変数を省略）で起動します。

起動時には通常どおりマイグレーション処理が実行されます。復元したバックアップに対して未適用のマイグレーションがある場合、それらはサーバー開始前に自動で適用されます。

起動後は、少なくとも次を確認してください。

- プロセスが正常に起動している
- マイグレーションエラーがログに出ていない
- 期待したデータが復元されている

## 注意事項

- 通常サーバーが完全に停止するまで `passdown backup restore` を実行しないでください。待機モードの終了確認前に通常サーバーを起動しないでください。
- 復元前の DB、`-wal`、`-shm` は退避されます。復元結果を確認するまでは削除しないでください。
- バックアップは DB と同じストレージ上に保存されるため、そのストレージ自体の障害には備えられません。
- 別マシンへの転送や暗号化は Passdown のバックアップ機能の対象外です。
